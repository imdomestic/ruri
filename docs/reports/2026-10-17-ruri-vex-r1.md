## 设置和数据

`experimental.vex.enabled` 存放在上游 state.json 的 AppSettings 中，默认关闭。CLI 使用既有命令 `ruri config set experimental.vex.enabled true --scope app`。服务器列表记录规范化 URL、显示名称、默认项目、用户 ID 和会话更新标记；每台服务器分别保存到钥匙串 `dev.ruri.launcher.vex.api`，进程内缓存按 URL 隔离。GUI 通过邀请登录，CLI 的 `login --token-stdin` 保留服务账号入口。

Vex 托管实例留在上游数据目录，并用 `vex-instance.json` 标记服务器 URL、项目和房间。实例索引同时包含服务器、项目、Minecraft、loader 和 loader 版本。验收使用 `.work/vex-real-it` 独立目录，旧独立应用的数据保持原状。

## 多服务器与邀请登录补充

执行依据为 `docs/directives/2026-10-18-ruri-vex-r1-servers-login.md`。设置页面支持添加地址或邀请链接、重命名、测试连接、设置默认服务器与默认项目、退出登录和删除服务器。邀请链接使用 Foundation URLComponents 解析；跨服务器邀请链接被拒绝。未登录时只请求公开 meta；兑换后的会话凭据写入对应 URL 的钥匙串条目。

服务器页和 Git 页按服务器、项目展示。每台服务器拥有独立 SSE 订阅和重连任务；GUI 加入流程复用对应服务器的事件流。服务器页、Git 页和设置页都显示该服务器实时更新的连接、断开及重新连接状态，收到有效 `sync` 后清除提示。每 15 秒重新检查当前用户、meta、可见项目和管理员可见的节点磁盘余量。401 只改变对应服务器的状态，并提供重新登录入口。服务不可达时仍清除本机登录；服务器端会话吊销由 logout 接口确认。配置管理的服务账号返回 conflict 时，客户端清除本机条目，结果中的 `remoteRevoked` 为 false。

CLI 提供 `vex servers add/list/remove/default`、`vex login/logout/whoami`。项目操作同时携带 `--server` 和 `--project`，输出包含服务器和项目；缺省选择使用默认值或唯一候选，存在歧义时列出候选。旧单服务器设置项不迁移。P1 后端声明 `auth.methods=["invite"]`；GitHub device flow 属于 P2，尚无可执行后端契约。
